Real Estate Demand Estimation

Geospatial Machine Learning & Macroeconomic Feature Compilation

Project Objective

The objective of this architecture is to mathematically prove if the London real estate market is driven entirely by physical geographic coordinates, or if macro-economic phenomena (like Bank of England interest rates, online digital demand, and real-time news sentiment) fundamentally dictate physical housing valuations.

Business Value

This pipeline constructs a production-ready, massive combinatorial ablation study over 3.9 million physical housing transactions. By bridging 4 distinct machine learning architectures (Neural Networks, XGBoost, Random Forest, LightGBM) with 4 external Data Providers (OSM, Google News, Trends, World Bank), we deliver a mathematically validated predictive engine capable of highly accurate localized pricing models for real estate investors and market analysts.

Data Exploration & Preparation

We downloaded the massive 3.2 GB UK National Property dataset (containing 28 million historical rows). Utilizing chunk-streaming memory management, we physically filtered out all non-London properties, cleaned the categorical strings (e.g. Property Type, Duration), and safely compressed the data into an extremely manageable london_data.csv containing precisely 3.9 million localized properties.

High-Level Architecture Design

This repository is structurally designed as a linear execution pipeline, built so that complete novices can easily understand how raw housing transactions are transformed into advanced geospatial AI predictions. * Data Prep Engine: Filters 28 million UK rows down to 3.9 million London properties. * Geospatial Mapping: Injects true Latitude and Longitude mapping coordinates. * API Feature Ecosystem: Scrapes real-time OpenStreetMap infrastructure, Google News sentiment, Google Trends, and World Bank lending rates. * Combinatorial Matrix: Trains 90 individual models simultaneously to isolate exactly which dataset drives price accuracy.

Train Models using (Latitude and Longitude)

Why was the Neural Network omitted from this step onwards?

During the initial non-spatial baseline tests, the Multi-Layer Perceptron (Neural Network) proved incredibly inefficient at processing tabular text features compared to Tree-based algorithms, resulting in the highest Absolute Error (£546,571). Neural Networks require normalized, dense floating-point matrices to function properly, making them computationally unstable when dealing with sparse categorical data like 30,000 unique postal districts. Therefore, it was logically decommissioned.

External Ecosystem API Feature Extraction & NLP Semantic Analysis

To fundamentally resolve the limitations of pure temporal and coordinate models, we architected pipelines to extract and compile massive external macro-economic API intelligence natively into the geometric data grid.

Advanced Model Applications (The 4 External Data Providers)

1. OpenStreetMap (OSM) API * Model Applied: scipy.spatial.cKDTree (Haversine Spatial Mathematics) * Why the Model is Applied ("Last Mile" Proximity): We explicitly DO NOT use bounded boxes like "Is there a station within 1.5 miles?". Bounding boxes are mathematically rigid. Instead, the KDTree searches an infinite boundary to instantly find the absolute closest node to the property, and applies the Haversine formula to compute the exact geographic Great-Circle distance over the curvature of the earth. * Resultset Extracted: distance_to_nearest_school_km, distance_to_nearest_hospital_km, distance_to_nearest_station_km, distance_to_nearest_bank_km.

2. Google News RSS API * Model Applied: HuggingFace sentence-transformers (SBERT Semantic NLP) * Why the Model is Applied (Sentiment vs Volume): We explicitly DO NOT predict based on the volume of news. Instead, we use SBERT to perform contextual Semantic Sentiment Analysis. We compute the Cosine Similarity between live news headlines and our target anchors. * Resultset Extracted: sbert_sentiment_index (A continuous float from -1.0 to +1.0).

3. Google Trends API * Model Applied: Temporal Demand Scaling * Why the Model is Applied: Housing prices "lag" reality. Conversely, internet searches "lead" reality. By integrating temporal search volume, we allow the ML models to predict sudden housing bubbles before the physical transaction data even catches up. * Resultset Extracted: google_trends_volume (A 0-to-100 normalized index).

4. World Bank (Bank of England) API * Model Applied: Macroeconomic Base Rate Matrix * Why the Model is Applied: The physical price of a house is entirely dictated by how expensive it is to borrow money from a bank. * Resultset Extracted: boe_interest_rate (The true national lending percentage).
